## ⚡ Action required — two manual steps to go live

### Step B — Register the webhook endpoint in Stripe Dashboard

> Do this once. It takes about 2 minutes.

1. Log in to [dashboard.stripe.com](https://dashboard.stripe.com) and make sure you are in **Live mode** (toggle in the top-left).
2. Go to **Developers → Webhooks → Add endpoint**.
3. Set **Endpoint URL**:
   ```
   https://ourheadwaters.ca/api/stripe/webhook
   ```
4. Under **Select events**, find and tick:
   - `checkout.session.completed`
5. Click **Add endpoint**.
6. On the endpoint detail page, click **Reveal** next to **Signing secret**.
7. Copy the `whsec_…` value — you'll need it in Step C.

### Step C — Save the live signing secret in Replit Secrets

1. In Replit, open the **Secrets** panel (padlock icon in the left sidebar).
2. Find `STRIPE_WEBHOOK_SECRET`.
3. Replace the current value with the `whsec_…` you copied in Step B.
4. Save.

> **Why replace it?** The existing value was generated by the Stripe CLI for local testing. The live Dashboard endpoint has its own different signing secret. If they don't match, the server will reject every live webhook with a 400 signature error.

### Step D — Confirm it works with a live test purchase

1. Open the Goodbye Kit Payment Link: `https://buy.stripe.com/28E7sNd4N399egs6fNbwk08`
2. Complete a purchase with card `4242 4242 4242 4242`, any future expiry, any CVC.
3. Check the inbox of the email you used — the magic-link delivery email should arrive within a few seconds.
4. In Stripe Dashboard → Developers → Webhooks → [your endpoint], confirm the event shows **Succeeded**.

| Secret | Where to find it | Required for |

| `STRIPE_SECRET_KEY` | Stripe Dashboard → Developers → API keys → Secret key | All Stripe operations |
| `STRIPE_WEBHOOK_SECRET` | Stripe Dashboard → Developers → Webhooks → [endpoint] → Signing secret (`whsec_…`) | Live kit purchase delivery |
| `KIT_WEBHOOK_SECRET` | Any strong random string | `POST /api/kits/purchase-webhook` — legacy manual webhook |
| `LIBRARY_OWNER_TOKEN` | Any strong random string | North Star / GORD kit-owner routes |

## Kit delivery flow (end to end)

1. Buyer completes purchase via the Stripe Payment Link.
2. Stripe fires `checkout.session.completed` to `https://ourheadwaters.ca/api/stripe/webhook`.
3. Server verifies the signature using `STRIPE_WEBHOOK_SECRET`, extracts `kit_id` from session metadata and buyer email from `customer_details.email`.
4. A 90-day access token is generated and written to the `kit_tokens` database table.
5. Event ID is written to `stripe_processed_events` DB table (idempotency guard — prevents duplicate emails on Stripe retries, safe across multiple service instances).
6. Magic-link delivery email is sent via the Google Mail connector.
7. Buyer clicks the link → `GET /api/kits/access/:token` → kit content.

## Troubleshooting

| Symptom | Likely cause | Fix |
|---------|-------------|-----|
| Webhook shows 400 in Stripe Dashboard | Wrong `STRIPE_WEBHOOK_SECRET` | Replace with the live signing secret from the registered endpoint |
| Webhook shows 200 but no email sent | Google Mail connector not authorized, or `kit_id` missing from metadata | Check connector status; confirm Payment Link metadata has `kit_id = goodbye-kit` |
| No webhook events appear at all | Endpoint not registered, or wrong URL | Re-check Step B — confirm URL is exactly `https://ourheadwaters.ca/api/stripe/webhook` |
| Duplicate delivery emails | Idempotency DB insert failed | Check `stripe_processed_events` table; ensure DB is reachable |
