## 2. The Eave Relationship

### What Zone 3 Can See
- All 807 institutional data: membership tiers, producer sales, round reports, board minutes, HST filings, grant applications, event records, partner inquiries
- Aggregated financial summaries (not raw household transactions)
- Producer-level sales data, accessible to that producer and admins only

### What Zone 3 Cannot Reach
- Bobbie's personal Zone 0/1 data (household finances, personal calendar, private messages) — this is structurally absent from the schema, not just hidden
- The workspace has no pull on Zone 0 data at all. There is no sync, no feed, no import path from household to institutional layer

### Technical Enforcement of the Eave

The Eave is enforced in four layers:

1. **Authentication (Clerk)** — `artifacts/api-server/src/middlewares/clerkProxyMiddleware.ts`. Every request must carry a valid Clerk session. Unauthenticated requests reach no data.

2. **Role middleware** — `requireAdmin`, `requireBoard`, `requireSeats("treasurer")` in route handlers. Board data (minutes, agendas, financial controls) is gated by seat. Producer data is scoped by `producer_slug` — producers can only read their own rows.

3. **Object ACL** — `artifacts/api-server/src/lib/objectAcl.ts`. File objects (NWHU forms, licences) carry a JSON policy stored with the object. `canAccessObject()` is called before any file is streamed. Policy values: `owner`, `admin`, or explicit seat list.

4. **Encryption at rest** — `encryptField` / `decryptFieldOrPassthrough` (AES-256-GCM). Applied to sensitive free-text fields: board minute bodies, partner inquiry messages, producer notes. Even a direct DB read returns ciphertext.

### Governance Model for Crossing the Eave
There is no formal consent/handshake protocol at this layer yet. The Eave is enforced technically (auth + RBAC + ACL) but there is no documented governance artifact — no consent record, no delegation model, no "Eave crossing" log. This is a gap.

## 3. The Governing Constraint

**The tenant seam is the load-bearing design constraint at Zone 3.**

Equivalent to the Saltbox at Zone 0, the tenant seam is the structural rule that prevents 807's board from becoming the platform operator. It reads:

> *Multi-tenancy is a Headwaters commercial decision. 807 is tenant `"807"` — the first licensee, not the vendor. The board has no authority to onboard or configure new co-op tenants.*

In code: `artifacts/api-server/src/config/tenant.ts` exports `getTenant()` which currently returns `"807"` unconditionally. The registry pattern is in place; the second slot is empty by design.

Consequence: every feature built for 807 must be architecturally reusable by a future tenant. Features that are 807-specific are isolated in tenant config files, not hardcoded into business logic.

## 4. Vocabulary Discipline

### Terms With Settled Definitions

| Term | Zone 3 Definition | Notes |
|---|---|---|
| **Round** | A single distribution event (one Wednesday pickup) | Used in `treasurer_round_reports`. Not interchangeable with Cycle. |
| **Cycle** | A monthly (4-week) producer payout period, Monday-anchored | `producer_payout_cycles` schema. Closes after all rounds in the window. |
| **Pickup** | A scheduled order collection point (day + town) | Configured per tenant. Missed pickups may be "paid forward" to food banks. |
| **Producer** | A member who sells goods through the co-op | Two streams: **Online** (Local Line only) and **Hub** (Online + shared storage + orientation) |
| **Member** | Anyone with a co-op membership | Two views: **Household** (Community members) and **Business** (Producers) |
| **Tier** | Informal — the code prefers **stream** or **class** for formal distinctions | "Tier" appears in UI copy; not in schema column names |
| **Tenant** | A Headwaters licensee (one co-op) | 807 is `"807"`. Tenant slug drives config lookup. |
| **Eave** | Not yet a first-class term in this codebase | Concept exists; no code symbol or constant named `eave` |

### Both-Sides Test (vernacular vs. grant language)
The clearest stress point is **producer** vs. **vendor**. In grant language (NOHFC, FedNor), 807's producers are called "vendors" or "local food producers." In co-op vernacular, they are members with producer status. The codebase uses `producer` throughout; grant applications use `vendor` in prose. No code-level reconciliation — this lives in the treasurer's head and in document templates.

**Round** also carries tension: internally it means one distribution event; externally (Local Line API) a "round" is their own concept. The two are mapped but not formally documented.

### Loose Edges
- **Hub** — means both the physical co-op hub location and the producer membership stream that includes shared storage. One word, two referents.
- **Coordinator** — used for market coordinators (Market Mosaic), partner shop coordinators, and informally for board members managing a domain. Not disambiguated in schema or middleware.

### Codetry Passes
No published codetry pass API endpoints. Vocabulary decisions are encoded in:
- `artifacts/807-benefits/src/config/audienceCopy.ts` — community vs. producer view language
- `artifacts/807-benefits/src/lib/season.ts` — NWO season definitions with explicit rationale
- `replit.md` — architectural decisions section (informal decision log)

### Database Privacy Decisions
- Sensitive free-text (board minutes, inquiry messages, producer notes) encrypted at rest with AES-256-GCM
- No `tenant_id` column on member-facing tables yet — tenancy enforced at application layer
- `BACKUP_ENCRYPTION_KEY` environment secret for backup encryption (separate from field-level key)
- No personal biometric or financial data at Zone 0 granularity — the schema stops at co-op transaction level

### AI Usage
- Grants Finder uses LLM matching for grant-to-project fit scoring. PII is redacted before the outbound call via `artifacts/api-server/src/lib/grants/redact.ts` — names, emails, org names, and dollar amounts are replaced with stable placeholders before the prompt leaves the server.
- No other AI in production routes.

### Cross-Project Dependencies
- **Zone 0/1 → Zone 3**: No declared dependency. Zone 3 does not pull from Zone 0.
- **Zone 3 → Rootwork (Zone 4/5)**: Rootwork practitioners are onboarded separately at `rootwork.coop`. The 807 platform does not push data to Rootwork. The dependency is referential (807 as proof case), not technical.

## 8. Locked Decisions

These should not be reopened without Bobbie's explicit instruction:

1. **Multi-tenancy is Headwaters' decision.** 807's board has no authority to onboard new tenants. The tenant seam exists for Headwaters to use, not 807 to configure.
2. **Clerk for authentication.** Not Replit Auth. Not rolling a custom session system.
3. **Square for payment processing.** Stripe Connect is modelled but not wired. The Square integration is live and trusted.
4. **Encryption at rest for sensitive free-text.** `encryptField` is applied at the route layer before insert. Removal would require a migration and a security review.
5. **One API server, shared by all artifacts.** Routes are path-prefixed. No separate API per artifact.
6. **The seasonal clock is NWO-specific.** Six seasons, not four. This is not cosmetic — it drives UI context. Do not flatten to standard seasons.
7. **"Rootwork" is the working name (not yet locked).** This is the one vocabulary decision explicitly held open by Bobbie as of May 2026.
