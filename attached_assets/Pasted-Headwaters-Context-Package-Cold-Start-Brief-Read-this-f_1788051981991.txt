Headwaters Context Package — Cold-Start Brief
Read this first. This is the single document a fresh agent (or new contributor) needs to orient in this codebase. It does not repeat detail — it points to the right file for each topic. Start here, then open whatever you need.

What this codebase is
Headwaters builds and licenses digital infrastructure for food co-operatives and community organizations in Zone 3 — Northwestern Ontario's 807 area code, boreal forest, long winters, and remote communities. This is not a generic SaaS project; the zone is a design constraint baked into every product. 807 Food Co-operative & Hub (Dryden, ON) is the flagship tenant and first licensee. The platform is explicitly multi-tenant so future co-ops can be onboarded without touching core code.

The codebase is a pnpm monorepo with React + Vite frontends, an Express 5 API server, PostgreSQL via Drizzle ORM, Clerk auth, and Square payments. There are currently eight deployed artifacts (seven web + one mobile) sharing a single API server and database. 807 is not the platform vendor — Headwaters is. Contributors reading multi-tenancy code should understand the "tenant seam" exists to serve future Headwaters clients, not future 807 initiatives.

Gotchas worth knowing cold
Kitchen Rental — /partners/kitchen-rental silently posts with role: "other", which routes to a specific board email in artifacts/api-server/src/config/board.ts.
Deadfall naming — Public brand is "Deadfall"; internal code (DB tables, API routes) remains /api/deadhead/*. Do not rename DB tables.
Deadfall spotter access — Spotters use HMAC magic-link tokens. Spotter links point to /deadfall/spotter/:id. Signed by DEADHEAD_SPOTTER_SECRET or falls back to SESSION_SECRET.
Deadfall triage sync — Triage mode (/deadfall/triage) syncs with .local/replit-tasks-cache.json via POST /api/deadhead/sync-tasks.
Multi-tenancy seam — The tenant seam is for future Headwaters licensees, not 807 sub-tenants. 807's board has no authority to configure new co-op tenants.
Market Mosaic = the target pattern — Its DB-driven multi-tenancy is the mature model. New features should follow it, not the static seam.
Never use console.log in server code — Use req.log in route handlers and the singleton logger for non-request code.
Do not run pnpm dev from workspace root — Run artifacts via workflows. Each needs PORT and BASE_PATH env vars wired by the workflow config.
